# MyBot Studio v0.3 — BETA

**Release type:** GitHub prerelease, not stable.
**Intended tag/title:** `v0.3-BETA` / `MyBot Studio v0.3 — BETA`.
**Application metadata:** `0.3.0` (backend `VERSION` and `frontend/package.json` aligned; the GitHub prerelease flag indicates release maturity).
**Branch:** `v0.3beta`, merged into `master` (the default branch).

## Highlights

This release is a **security and correctness pass** over the v0.2 feature set. Nothing in the canvas, keyboard or simulator behaviour is changed; what changes is how the panel API authenticates callers, how it localizes every message, and how it refuses unvalidated flow templates.

- **Default-deny API authentication.** A `Bearer` token issued by this backend is now required on every `/api` route except the public health/login/webhook/media/i18n-read paths. Enforcement is middleware in `app/main.py` that runs *before* route code, plus an explicit `require_admin` dependency on every admin router. A route added later is protected even if the middleware is bypassed.
- **Fail-closed configuration.** `app/config.py` no longer ships a guessable `JWT_SECRET` or a `DEFAULT_ADMIN_PASS`. A blank signing key raises `RuntimeError` at boot instead of silently running on a shared secret; CORS is now an explicit origin list.
- **Localized API responses.** Every user-visible string in the auth, bot, flow, font, language-pack, system, simulator and webhook endpoints is resolved from `backend/locales/<code>.json` (`en`, `fa`, `ar`, `ru`) through `t(key, language_from_request(request), ...)`. Python exception text no longer reaches the browser: the simulator logs the traceback server-side and returns a translated sentence.
- **Validated flow imports.** `POST /api/flows/{bot}/import` runs `app/core/flow_plan.py::validate_flow` before writing: unknown node types, dangling or duplicate edges, a graph without a trigger, and `callback_data` beyond Telegram's 64-byte limit are refused with HTTP 422, and the stored flow keeps its previous content and version.
- **SSRF + upload hardening.** `app/core/net.py::validate_outbound_url` enforces scheme, host and private/loopback IP for proxy and Cloudflare-Worker settings (opt-in via `ALLOW_PRIVATE_URLS`). Language-pack and font uploads validate the derived name, resolve the destination, and reject anything outside the target directory.
- **Random per-install signing keys.** `start-local.py` (Python `secrets`), `install.bat` (PowerShell `RandomNumberGenerator`) and `install.sh` (shell `urandom`) each generate a unique `JWT_SECRET`; `deploy/docker-compose.yml` now fails closed with no fallback key.
- **Test infrastructure.** New backend suites (`test_auth_required`, `test_flow_import_validation`, `test_i18n_contract`), `backend/pytest.ini` + `requirements-dev.txt`, a `conftest.py` that seeds a throwaway `JWT_SECRET` for the fail-closed config, and a CI workflow that runs the locale guardrail, the backend suite, the frontend audits and the Vite build on every push/PR.

## Localization contract

`scripts/check_i18n.py --scan` enforces the backend contract:

1. **Key usage** — every `t("...")` / `message("...")` key used in `backend/app` exists in every shipped pack, so no language ever renders a raw key.
2. **Parity** — the four packs stay key-identical against `en.json`; adding a string to one file is caught the same day.
3. **Hardcoded copy** — reports user-facing string literals that must be a locale key instead. Prompt/tool-definition modules are exempt (their literals are LLM instructions, not UI copy — see `AGENTS.md`, "Prompt language").

The panel mirrors the rule with `frontend/src/locales/i18nAudit.test.mjs` (run via `npm test`): bundled locales have matching nonempty keys and interpolation variables, literal `t()`/`label()` calls resolve in every locale, component JSX/`label` attributes carry no authored prose, and the finite node/keyboard/media/tracked-field key families resolve.

Adding a language means dropping a new `<code>.json` into `backend/locales/` and `frontend/src/locales/`, installing it through `/api/i18n/upload` for the backend pack, and re-running both audits.

## Upgrade caveats

- **Back up first.** This is a prerelease; back up `.env`, the databases (`backend/data/`, `bot_{id}.db`) and `backend/uploads/` before upgrading.
- **Existing panels will need a token.** Because the API now requires a `Bearer` token, browsers that were not authenticated are answered 401. The panel's `authFetch` handles the first 401 by clearing the session and logging out, so a user at an idle panel is re-prompted for login. This is intended, not a regression.
- **`JWT_SECRET` is required.** A fresh install that did not generate one (older launchers) will not boot until it has a `JWT_SECRET`. The v0.3 launchers generate it; a hand-edited `.env` must supply it.
- **Flow versions are a counter, not a timestamp.** `validate_flow` leaves `version` untouched on a rejected import. Canvas saves are unrestricted, so a half-finished graph is a normal editing state, not an error.
- **Self-update is off by default.** `ENABLE_SELF_UPDATE` must be set explicitly before the `/api/system/update` endpoint will act; otherwise it returns 403.
- **Webhook + media stay public.** Telegram and the login screen cannot sign requests, so `/api/webhook/*`, `/media/*` and the i18n read endpoints remain open. Restrict the panel to a known client origin via `CORS_ORIGINS` and put it behind a trusted proxy.

## Install / upgrade

Use the complete repository checkout. From its root:

- Windows: `.\start-local.bat`
- Linux / macOS: `bash start-local.sh`
- Both invoke `start-local.py`. Add `--check` for dependency/import preparation only: it does not launch services, is not read-only and does not prove startup or health.
- Python 3.10+ with pip/venv, Node.js 18+ with npm (prefer a supported LTS), and network access for dependencies are needed; uv is optional. Keep port 8000 free because the launcher may terminate its listener.
- For Docker, review `install.sh` (Linux) or `install.bat` (Windows) and run it from a full checkout; it generates a random signing key and builds the panel and bot-engine services.

## Verification

The locale guardrail, the backend suite (120 tests including the three new ones), the frontend audits and the Vite build are all run by CI on every push/PR. The `conftest.py` guarantees the fail-closed `JWT_SECRET` check never crashes collection in a clean CI environment. Actual pass counts are published by the release process, not asserted here.
